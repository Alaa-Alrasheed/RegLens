What we are building

A Python tool that reads the CAR regulations, splits them into articles, and finds four kinds of problems: conflicting values (e.g. records kept 2 years vs 3 years), duplicate or divergent definitions versus CAR-DEF, broken references (to missing articles or mismatched ICAO editions), and duplicate or overlapping requirements. Every finding cites regulation + article number, quotes both sides verbatim, and proposes one action: move to a common regulation, cross-reference, harmonize wording, or keep with justification.

A Streamlit review screen lets the expert accept, modify or reject each finding. The official text is never edited. The AI drafts unified wording on request, marked "not approved" until an expert signs off. Results export to Excel.

The demo story (60 s): load the regulations → 9 findings appear → open "maintenance records: 2 vs 3 vs 5 years" → show the quotes side by side → click "Draft unified wording" → expert accepts → export to Excel → show "found X of Y expert-labeled cases".

Merge rules

  1. Each person commits only the files they own. There are no shared files, so there are no merge conflicts.
  2. Only the lead changes the contract. If an agent wants a new field, it goes in extra, never as a new top-level field.
  3. Every module must run on data/mock_articles.json or data/mock_findings.json without the other modules present.
  4. Every cross-module import goes inside try/except. A broken module shows "not available"; it never crashes the demo.
  5. Stop adding features at T+45. After that, only fixes.
